# Improvements Backlog

The single source of truth for planned improvements to this boilerplate. Lives in
the repo so it propagates to every fork (unlike issues) and is readable by agents
(unlike chat history).

## Protocol

- **Agents**: read this file before proposing architectural work. When you complete
  an item, mark it `done` with the commit hash. Do not re-propose items in the
  "Decided / won't do" section without writing a new ADR.
- **Humans**: approve priority changes. New items enter as `proposed` with a
  one-line rationale tied to the drift risk they close.
- Status values: `proposed` | `in-progress` | `done (<commit>)` | `deferred (<why>)` | `rejected (<why>)`
- Each item names the **enforcement layer** it belongs to:
  `compiler` | `gate` | `test` | `stub/adr` | `docs` | `ci` | `process`

| Hand-rolled `Html` ADT, not Halogen/Smolder/Flame | Smolder is orphaned; Halogen/Flame are client-side frameworks, wrong shape for SSR MPA. ADR-001 |
| Thin `node-http` wrapper, not HTTPurple/Express | 303-line auditable file beats framework abstraction for a starter; invariants (body cap, security headers, path safety) are explicit |
| Hand-rolled `Dictionary` i18n, not `simple-i18n`/gettext | Record-typed `en`/`fr` gives *compile-time* bilingual completeness; map-based libs move failures to runtime |
| No pre-stubbing `App.Search` / `App.RealTime` | Interface depends on implementation choice; premature stub locks in a wrong shape |
| No `Feature` typeclass / generic form decoder | Over-engineering at current scale; parallel `decodeX` until 5+ forms, then extract |
| Session cookies over JWT (auth) | SSR MPA fits server-side sessions; JWT only if a second (API) client appears. ADR-002 |
| **Dead libraries — do not use**: `purescript-postgresql-client` (rightfold, repo deleted), `purescript-foreign-generic` (paf31, superseded by `open-foreign-generic`), `purescript-node-bcrypt` (lpil, archived), `purescript-jwt` (menelaos, decode-only) | Common blog-post references that lead agents to abandoned code |
| Language: **PureScript** over TS+Effect / ReScript / Haskell | Language-enforced strictness beats discipline-enforced for unreviewed agent work (no `any`, no `as`, no bypass compiles). npm coverage comes via FFI taming (ADR-003). Haskell/ReScript/Effect-TS evaluated; revisit only if the ecosystem fundamentally shifts |
- **`make new-feature` script** — tracked as #43 (proposed)
| Server runtime: **node:http API surface, run on Bun** — not `Bun.serve` FFI | Verified in vendored Bun 1.4.0 source: node:http is implemented on Bun.serve (`_http_server.ts:674`) with lazy headers, streamed bodies, and `requestTimeout` (300s default) — the compat layer is good and our invariants hold as written. Rewriting on Bun.serve = new security-critical code and two-backend drift. **User committed 100% to Bun (Aug 2026)** — the portability argument no longer applies, but the decision stands on the other grounds. Selective Bun taming (#31, #33) is the sanctioned path; AGENTS.md dual-runtime claim removal tracked in #34. **Superseded by ADR-007 (proposed, #41)**: the Bun.serve migration guide reverses this decision — streaming SSR, type-safe prefetching, and the spurs.icaro.fr Vary/prefetch bug make the rewrite worth the one-time cost. The decision was right at the time; the inputs changed. |
